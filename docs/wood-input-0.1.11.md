# 0.1.11 木质输入栏

按用户提供的参考图调整底部输入栏：800×600逻辑画布中，框体位置 x=48、y=494.4，宽704、高76.8；左侧浅色输入区，右侧三枚石头按钮。字体、控件、留白随游戏画布等比缩放。生成时发送原位变成取消，不额外追加第四个按钮；中英文及录音/识别状态仍可显示，声音开关保持原设置。

没有找到与参考图完全相同的整条原版木框，也没有把截图抠图或 AI 图当作游戏素材。当前为明确标记的原版素材组合，不能宣称纹理与参考图逐像素一致：

首次尝试原版 ZombieNote 纸张时，缩小后出现不合适的斜边，已更换为原版空白控件；当前发行构建不使用该尝试方案。

生成位置在 `prepareChatArtwork`，产物仅存在本机资源缓存并记录 sources。公开构建不随包分发这些游戏媒体。桌面旧缓存缺少素材时，从随包已审计 PAK 提取两张所需图片并重新组合，不修改游戏或聊天数据；公开桌面包未附 PAK 时保留原控件回退。新导入 Web 资源会直接包含新组合；旧 Web 缓存可在选项→游戏→更新原版界面资源中选取 main.pak 更新，不必清除存档。

61项单元测试通过。`tests/wood-input-desktop.mjs` 检查多种窗口尺寸的控件边界、取消时仍为三枚按钮、发送/取消/记录、中英文，并模拟旧资源缓存验证更新前后的游戏记录完全相同。使用本地模拟 LLM，不调用付费服务，不录制麦克风。真实 Chrome 的生产 Web 导入/聊天/全文复制/剪贴板拒绝回归通过。报告与截图在 `private/reports/wood-input/`；最终安装检查以 installed.json 为准。

按 React 检查规范复核了既有组件：保留事件处理与状态边界，新增资源升级只在缺少缓存素材时运行；控件使用现有按钮与字体，没有引入新 UI 库。视觉核对采用实际运行截图，未把构建成功当作截图验收。

0.1.12 补充：用户指出“记”字处竖缝，放大运行截图确认是三段按钮背景的分数像素拼接露底，与中文字形无关。中段背景加宽2个CSS像素，与两端各重叠约1像素，保持原贴图、字体和布局。底栏与复制按钮均修正，包内多尺寸/发送取消/记录/英文/资源缓存升级回归通过；放大截图 private/reports/record-seam-fixed.png 确认原竖缝消失。
